# Бинарные форматы данных ARGUS

Общие правила: little-endian, фиксированные размеры полей, у каждого файла магия и версия.
Данные, которые читает GPU (вершины, пиксели текстур), лежат по смещению, кратному 16.
Файлы собираются `tools/*.py` из исходников в `assets/` и `levels/`, кладутся в `build/assets/`
и копируются в `build/ARGUS/data/`. Загрузчики — в `core/` (чистый C, без PSP-заголовков).

## AMSH — статический меш (`*.msh`)

| Смещение | Тип | Поле |
|---|---|---|
| 0 | char[4] | `"AMSH"` |
| 4 | u32 | версия = 1 |
| 8 | u32 | формат = 1 (static) |
| 12 | u32 | число вершин (кратно 3) |
| 16 | f32[3] | bbox min |
| 28 | f32[3] | bbox max |
| 40 | — | нули до 64 |
| 64 | вершины | N × 28 байт |

Вершина: `f32 x,y,z; f32 nx,ny,nz; u8 slot; u8 ao; u16 pad`. Треугольники — тройками подряд,
обход против часовой стрелки снаружи (`GU_CCW`). Цвета в файле нет: `slot` — индекс палитры,
`ao` — множитель затенения; RGB считается при загрузке (`mesh_recolor`).

## APAL — палитры регионов (`palettes.pal`)

Заголовок: `char[4] "APAL"; u32 версия = 1; u32 count`. Далее count записей по 64 байта:
`char name[16]; u32 sky_top; u32 sky_bottom; f32 fog_near; f32 fog_far; u32 slots[8]`.
Цвета — `0xAABBGGRR`. `fog_near/fog_far` — смещения глубины относительно цели камеры.

## AFNT — шрифтовой атлас (`font.bin`)

Один файл: метаданные + пиксели. Атлас — 8-битная альфа (`GU_PSM_T8`), CLUT строится в коде:
запись i = `(i << 24) | 0x00FFFFFF`, режим `GU_TFX_MODULATE` красит текст цветом вершины.

Заголовок (32 байта):

| Смещение | Тип | Поле |
|---|---|---|
| 0 | char[4] | `"AFNT"` |
| 4 | u32 | версия = 1 |
| 8 | u32 | tex_w (512) |
| 12 | u32 | tex_h (512) |
| 16 | u32 | face_count (≤ 4) |
| 20 | u32 | pixels_offset (кратно 16) |
| 24 | u32 | pixels_size (= tex_w × tex_h) |
| 28 | u32 | резерв = 0 |

Далее face_count записей по 20 байт:
`u16 px_size; u16 line_height; i16 baseline; u16 glyph_count; u32 glyph_offset;
u16 kern_count; u16 pad; u32 kern_offset` — смещения от начала файла.

Глиф (16 байт, таблица отсортирована по `codepoint` для двоичного поиска):
`u32 codepoint; u16 u; u16 v; u8 w; u8 h; i8 xoff; i8 yoff; u8 advance; u8 pad`.
`u,v` — левый верхний угол в атласе; `xoff,yoff` — смещение от точки пера (yoff вниз от
базовой линии вверх отрицателен); `advance` — шаг пера.

Кернинг (8 байт, отсортирован по ключу `first << 16 | second`, индексы глифов, не кодпоинты):
`u16 first; u16 second; i8 dx; u8 pad[3]`. `kern_count` может быть 0.

Пиксели: `pixels_size` байт альфы, строка = tex_w байт, без свизлинга.

## ASTR — таблица строк (`strings_<lang>.bin`)

`char[4] "ASTR"; u32 версия = 1; u32 count; u32 резерв`, далее `u32 offsets[count]`
(от начала файла), далее UTF-8 строки, каждая с завершающим нулём. Порядок строк = порядок
идентификаторов в сгенерированном `strings_ids.h` (`enum { STR_… , STR_COUNT }`).
Источник — `assets/strings.csv` с колонками `id,ru,en`.

## ALVL — остров (`*.lvl`)

Заголовок (96 байт):

| Смещение | Тип | Поле |
|---|---|---|
| 0 | char[4] | `"ALVL"` |
| 4 | u32 | версия = 1 |
| 8 | char[16] | имя уровня (латиницей, с завершающим нулём) |
| 24 | char[16] | имя палитры в `palettes.pal` |
| 40 | u16 | cells_x |
| 42 | u16 | cells_z |
| 44 | f32 | cell_size (мировых единиц на клетку) |
| 48 | f32 | step_y (высота одного шага) |
| 52 | f32 | spawn_x (мировые) |
| 56 | f32 | spawn_z |
| 60 | f32 | spawn_yaw (градусы) |
| 64 | u16 | entity_count (≤ 128) |
| 66 | u16 | link_count (≤ 128) |
| 68 | u16 | portal_count (≤ 8) |
| 70 | u8 | cam_angle (0..3) |
| 71 | u8 | cam_lock (0/1) |
| 72 | u32 | cells_offset (кратно 4) |
| 76 | u32 | entities_offset (кратно 4) |
| 80 | u32 | links_offset (кратно 4) |
| 84 | u32 | portals_offset (кратно 4) |
| 88 | u32 | name_str_id (`STR_*` или 0xFFFFFFFF) |
| 92 | u32 | резерв = 0 |

Клетка (4 байта, `cells_x × cells_z` подряд, порядок строк по z): `u8 height; u8 flags; u8 segment; u8 pad`.
Флаги: 1 EXISTS, 2 WALK, 4 STAIR, 8 WATER, 16 FLOAT, 32 SEG (см. `core/level.h`).
Мировые координаты центра клетки: `x = -cells_x·cell/2 + (cx + 0.5)·cell`, аналогично z.
Верх клетки: `y = height · step_y`.

Сущность (48 байт): `u16 type; u16 flags; f32 x,y,z; f32 yaw_deg; i32 params[6]; u16 name_str_id; u16 id`.
`type` — код из сгенерированного `entity_types.h` (источник — `assets/entities.toml`, порядок строк задаёт коды,
добавлять только в конец). `id` уникален внутри уровня и не равен нулю.

Связь (8 байт): `u16 src_id; u8 src_out; u8 pad; u16 dst_id; u8 dst_in; u8 pad2`.

Портал (16 байт): `u16 cx; u16 cz; u8 w; u8 h; u16 target_level; u16 target_entry; u16 pad; u32 pad2`.
`target_level` — код из сгенерированного `level_ids.h` (`LVL_*`), `target_entry` — id сущности-входа или 0.

### Исходник уровня (`levels/*.toml`)

```toml
name = "hub"          # совпадает с именем файла
palette = "hub"
cell = 1.0
step = 0.5
base_depth = 3.0      # насколько стены уходят в пустоту
cam_angle = 0
cam_lock = false
spawn = [8.5, 12.5]   # в клетках, дробные
spawn_yaw = 180.0
caption = "HUB_CAPTION"   # идентификатор строки без префикса STR_

map = """             # высоты: '.' пусто, 0-9 и a-f — шаги
...222...
"""
stairs = """..."""    # необязательный слой: 'x' — рампа
water  = """..."""    # необязательный слой: 'x' — вода
floats = """..."""    # необязательный слой: 'x' — плавучая клетка
segments = """..."""  # необязательный слой: цифра 1-9 — номер сегмента
seg_states = """..."""# необязательный слой: цифра 0-3 — при каком состоянии сегмента
                      # клетка проходима (по умолчанию 0)

[[entity]]
type = "ECHO"         # имя из assets/entities.toml
id = 1
cell = [4.5, 6.5]     # в клетках, дробные; высота берётся из карты
y = 4.55              # необязательно: высота вручную, если не с пола (хвост на постаменте)
yaw = 90.0
name = "ECHO_1"       # необязательно, идентификатор строки без STR_
params = [0, 0]

[[link]]
from = [1, 0]         # [id сущности, номер выхода]
to = [2, 0]           # [id сущности, номер входа]

[[portal]]
cell = [8, 15]
size = [1, 2]
to = "mirrors_1"      # имя уровня
entry = 0
```

Генератор `tools/levelc.py` собирает из одного TOML два файла: `<имя>.msh` (геометрия острова
с запечённым AO, формат AMSH) и `<имя>.lvl` (данные, формат ALVL), а также общие для всех уровней
`level_ids.h` (enum `LVL_*` и таблица имён файлов) и `entity_types.h` (enum `ENT_*`).

### Плавучие клетки и уровень воды

Клетка со слоем `floats` получает флаг `CELL_FLOAT`. Её пол берётся не из карты высот,
а из уровня воды: `level_t.water_steps × step_y` (`cell_floor` в `core/walk.c`). Это плот —
он всплывает и опускается вместе с водой, а зайти на него и сойти можно, только пока
перепад укладывается в шаг персонажа (0,55). Уровень воды, как и состояния сегментов,
в файле не хранится: его ставит `water_set_level` из `core/puzzles.h`, стартовое значение
берётся из минимума первого шлюза уровня при `entities_init` (без анимации всплытия).

Клетка `water` без `floats` остаётся непроходимой: это поверхность воды, а не плот.

### Вращающиеся сегменты

Байт `segment` клетки несёт номер сегмента в младших 6 битах и требуемое состояние в старших двух
(`CELL_SEG_ID` / `CELL_SEG_STATE` в `core/level.h`). Клетка с флагом SEG проходима, когда
`level_t.seg_states[номер]` равно требуемому состоянию. Сами состояния в файле не хранятся —
это состояние игры, которым управляет `segment_rotate` из `core/puzzles.h`.
В исходнике уровня за это отвечают два слоя: `segments` (цифра 1–9 — номер сегмента) и
`seg_states` (цифра 0–3 — при каком состоянии клетка проходима; по умолчанию 0).

### Панель памяти и кнопки-постаменты

`MEMORY_PANEL` хранит ожидаемую последовательность в `params[0..3]`, её длину —
в `params[4]` (ноль означает «считать ненулевые параметры»). Ввод идёт двумя способами:
нажатие по самой панели подаёт следующее значение по порядку (так решается простая
последовательность 1,2,3,4, которой семейство вводится), а кнопка-постамент `TRIGGER`
подаёт своё значение `params[0]` в панель `params[1]` — на этом строится настоящая
головоломка: запомнить порядок огней в зале и нажать постаменты в нём.
Ошибка сбрасывает прогресс панели, собранная последовательность включает её выход.

### Спящие стражи

`SLEEPER` ходит по кругу вокруг своей клетки, пока на него не смотрят, и занимает
клетку как камень: под взглядом он замирает и проход либо открывается, либо
запирается. `params[0]` — радиус круга в десятых клетки (по умолчанию 1,0),
`params[1]` — скорость в градусах в секунду (по умолчанию 30), `params[2]` —
начальная фаза в градусах. Фаза нужна, чтобы несколько стражей не ходили
синхронно: иначе узкий коридор либо всегда свободен, либо всегда закрыт.

### Двери

Ходьба знает только сетку, поэтому дверь запирает проход через сегмент: её клетки
помечаются в `segments` номером N, в `seg_states` — состоянием 1, а у сущности `DOOR`
`params[0] = N`. `entities_propagate` пишет состояние двери в `level_t.seg_states[N]`,
и закрытая дверь делает свои клетки непроходимыми.

### Уточнения к AFNT (проверено реализацией)

Запись глифа занимает 16 байт: перечисленные поля дают 14, последние два — выравнивание,
писатель их нулит, загрузчик не читает. `glyph_offset` и `kern_offset` кратны 4:
таблицы читаются на месте (на MIPS невыровненный доступ к `u32` — исключение).
`pixels_size` строго равен `tex_w × tex_h`. Размер атласа — степень двойки от 16 до 512.
Таблица глифов строго возрастает по `codepoint`, таблица кернинга — по ключу
`first << 16 | second`; индексы глифов в парах меньше `glyph_count`; пары с `dx = 0`
не пишутся. Загрузчик отвергает файл при нарушении любого из этих условий.

### Уточнение к ASTR

Число строк в файле должно совпадать со `STR_COUNT` из сгенерированного `strings_ids.h`;
игра отвергает набор с другим числом строк, иначе устаревший файл сдвинул бы все
идентификаторы. Последний байт файла — нулевой.
