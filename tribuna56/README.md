# Трибуна+ — трансляции детского спорта в Оренбурге

Сайт-сервис видеосъемки и прямых трансляций детских (10–16 лет) спортивных
матчей. Ключевая механика: каталог предстоящих матчей уже загружен на сайт —
клиент выбирает свой матч, отмечает услуги, и заявка приходит владельцу
в Telegram полностью сформированной.

- Публичная часть: каталог матчей с фильтрами, страницы матчей с embed-плеером
  VK Видео, форма заявки с мгновенным калькулятором стоимости и проверкой
  занятости оператора.
- Админка (`/admin.html`): CRUD матчей, очередь импорта из внешних источников,
  заявки со статусами.
- Импортёр: адаптеры источников расписаний → очередь подтверждения → каталог.

## Стек

Статика без сборки: HTML + нативные ES-модули + `api/*.js` (Vercel
serverless). Без npm-зависимостей. БД — Supabase (Postgres) через PostgREST
REST API обычным `fetch`. Тесты — встроенный `node --test`.

```
tribuna56/
├── index.html        главная (каталог, услуги, форма заявки)
├── match.html        страница матча (/match/:id через rewrite)
├── admin.html        админка (вход по ADMIN_TOKEN)
├── privacy.html      политика конфиденциальности (152-ФЗ)
├── db/schema.sql     схема БД — применяется в Supabase SQL Editor
├── assets/           стили, данные, чистая логика, DOM-слои
├── api/              serverless-функции (+ api/_lib/ — общие хелперы)
└── test/             юнит-тесты (node --test)
```

## Локальный запуск

```bash
npm run dev    # статика на http://localhost:3456 (каталог — демо-данные)
npm test       # юнит-тесты
```

Полный стек локально (serverless + env): `vercel dev` из этой папки.
Без настроенных env всё деградирует молча: каталог показывает демо-данные
на localhost, заявка отвечает «принято» с предупреждением в логах.

## Настройка (один раз)

### 1. База данных — Neon (рекомендуется) или Supabase

Слой БД двухбэкендовый, выбор автоматический по env: есть `DATABASE_URL` →
Neon; есть `SUPABASE_URL`+`SUPABASE_SERVICE_KEY` → Supabase (PostgREST).

**Neon через Vercel Marketplace (самый короткий путь):**
1. Vercel Dashboard → проект → Storage → Create Database → **Neon** →
   подключить к проекту. `DATABASE_URL` появится в env автоматически.
2. Neon Console → SQL Editor → вставить содержимое `db/schema.sql` → Run.
   (Блок RLS в конце схемы нужен только Supabase; в Neon выполнять его
   безопасно, можно не вырезать.)
3. Redeploy проекта в Vercel, чтобы функции увидели новую переменную.

Free-тариф Neon засыпает между запросами и просыпается сам за ~секунду —
в отличие от Supabase, специальный keep-alive не нужен.

**Supabase (альтернатива):** [supabase.com](https://supabase.com) → New
project (регион EU) → SQL Editor → `db/schema.sql` → Run → Settings → API:
`Project URL` и ключ `service_role` (НЕ anon) в env Vercel. Особенность
бесплатного тарифа: проект «засыпает» после ~7 дней без API-запросов —
ежедневный cron-импорт держит его живым.

### 2. Telegram-бот

1. В Telegram: @BotFather → `/newbot` → получить токен.
2. Написать своему боту любое сообщение, затем открыть
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и взять `chat.id`.

### 3. Vercel

1. New Project → импорт этого git-репозитория.
2. **Root Directory: `tribuna56`**, Framework Preset: Other, без build-команды.
3. Settings → Environment Variables:

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | автоматически от интеграции Neon (либо задайте Supabase-пару ниже) |
| `SUPABASE_URL` | `https://<ref>.supabase.co` — только если выбран Supabase |
| `SUPABASE_SERVICE_KEY` | ключ `service_role` — только если выбран Supabase |
| `TELEGRAM_BOT_TOKEN` | от @BotFather |
| `TELEGRAM_CHAT_ID` | id чата владельца |
| `ADMIN_TOKEN` | `openssl rand -hex 32` — пароль админки |
| `CRON_SECRET` | `openssl rand -hex 32` — Vercel сам шлет его в заголовке cron |
| `VK_SERVICE_TOKEN` | опционально: сервисный ключ приложения VK — автодетект эфиров группы (LIVE/finished сами) и VK-адаптеры импортёра |
| `VK_GROUP_ID` | опционально: числовой id группы (по умолчанию 241086908 — vk.com/tribuna_plus) |

Cron `0 3 * * *` UTC (8:00 по Оренбургу) подхватится из `vercel.json`.

## Табло для OBS-трансляций

Фирменная плашка счета поверх эфира. Два файла:
- `/scoreboard.html` — оверлей (Browser Source в OBS, фон прозрачный);
- `/console.html` — пульт: счет, часы, периоды, удаления.

Режимы:
- **Онлайн-пульт** (нужна БД): `/console.html` → «Создать онлайн-табло» —
  сгенерирует id+ключ и покажет две ссылки: оверлей для OBS и пульт для
  человека, ведущего счет с телефона. Оверлей опрашивает
  `/api/scoreboard?id=…` раз в 2,5 с; часы тикают локально, так что
  секундомер плавный.
- **Локальный** (без БД): пульт открывается КАСТОМ-ДОКОМ в самом OBS
  (View → Docks → Custom Browser Docks → URL `/console.html?local=1`),
  оверлей — `/scoreboard.html?local=1`. Синхронизация через общий
  localStorage движка OBS.

Хоккейное время идет на убывание (20:00 → 0:00), футбольное — вверх;
коррекция и поле «Выставить мм:сс» работают в экранных величинах —
вводится то, что на табло арены. Одно табло = один эфир: для
параллельных трансляций создается по табло на каждую (список своих —
на стартовом экране пульта).

Параметры оверлея: `?scale=1.5` — размер плашки, `?demo=1` — предпросмотр
с тестовыми данными. Логотипы команд подтягиваются как на сайте
(`assets/badges.js`): точное имя клуба → реальное лого, иначе монограмма.

Если БД уже развернута ранее — выполните в SQL-редакторе блок
`scoreboards` из `db/schema.sql` (новая таблица + RLS).

## Брендинг

Название, контакты, услуги и цены — в `assets/data.js` (константа `BRAND`,
`SERVICES`, `SPORTS`). Палитра — CSS-переменные в начале `assets/styles.css`.
Смена названия = правка одного файла.
